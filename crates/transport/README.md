# transport

How kv pages move between workers.

- `tcp`: a page run's bytes over a plain TCP stream (the bulk link). Every
  build has it; it is what peers without a shared backend use.
- `nixl` (feature): a worker's kv read in place, page to page, through
  NIXL. A worker whose engine exports its kv (`offload.transfer` not
  `inline`) registers it with one NIXL agent; a peer of the same layout
  reads it device to device. UCX picks the path: CUDA IPC or shared memory
  on one host, RDMA across hosts.

## Building with NIXL

The `nixl` feature links `libnixl_capi.so` and its dependencies from an
assembled install named by `NIXL_PREFIX`. The NIXL wheel carries all of it:

```sh
pip download --no-deps --only-binary=:all: -d /tmp/nixl nixl-cu13   # or nixl-cu12
mkdir -p /tmp/nixl/x && cd /tmp/nixl/x && python3 -I -m zipfile -e ../nixl_cu13-*.whl .
P=$HOME/.pie/nixl
mkdir -p $P/lib/plugins $P/lib/ucx
cp -a .nixl_cu13.mesonpy.libs/*.so* nixl_cu13.libs/*.so* $P/lib/
cp -a .nixl_cu13.mesonpy.libs/plugins/*.so $P/lib/plugins/
cp -a nixl_cu13.libs/ucx/*.so* $P/lib/ucx/
(cd $P/lib/ucx && for f in *.so.0.0.0; do ln -sf $f ${f%.0.0.0}.0; ln -sf $f ${f%.0.0.0}; done)
```

The bindings are generated by bindgen, which needs libclang (`LIBCLANG_PATH`,
for instance from `pip install libclang`) and, if that libclang ships no
builtin headers, a C include directory:

```sh
NIXL_PREFIX=$HOME/.pie/nixl \
LIBCLANG_PATH=<dir holding libclang.so> \
BINDGEN_EXTRA_CLANG_ARGS="-I/usr/lib/gcc/x86_64-linux-gnu/13/include" \
cargo build --release --features cuda,nixl -p pie
```

At run time the agent finds its plugins and UCX its modules through
`NIXL_PLUGIN_DIR=$NIXL_PREFIX/lib/plugins` and
`UCX_MODULE_DIR=$NIXL_PREFIX/lib/ucx`.

On a host without NVLink, UCX keeps CUDA IPC reads off, and without RDMA
devices (`/dev/infiniband`) or ptrace (for `cma`) it falls back to TCP
emulation, slower than the `tcp` link: measure on the hardware it is meant
for.
