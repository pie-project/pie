# Pie 0.5 (preview)

Unreleased. Interfaces described here may change before release.

The central change is the programming model. Through 0.4, an inferlet drove
generation from the host, one token at a time. In 0.5 an inferlet defines a
dataflow of tensor programs, submits passes onto a pipeline, and exchanges
values with the running dataflow through channels.

Parts I to III cover that model and what it makes expressible. Part IV covers
the rest of the release: model loading, weight streaming, the Metal driver, and
the scheduler, none of which depend on it.

1,206 commits since 0.4.0. 3,195 files changed, +603,268 / −244,709 lines.
Host workspace: 3 crates → 55.

## Forward pass programming

### What the previous model cost

In the eager model the host built a pass, submitted it, waited for logits,
sampled, checked the stop condition, and submitted again. The sampling and stop
logic sat between forward passes, so the device idled for one host round trip
per token.

Two further limits followed from the same structure. Samplers were a closed WIT
enum, so a new sampling method meant an engine change. And an inferlet could
only compute on the host. That put tensor-level algorithms out of reach, such as
KV eviction driven by attention scores.

### The model in 0.5

An inferlet defines a dataflow once, as stages of PTIR programs, and submits
passes of it onto a pipeline. `submit()` returns immediately and the pipeline
keeps several passes in flight. While the dataflow runs, the inferlet interacts
with it only through channels.

### Side by side

| | 0.4 | 0.5 |
|---|---|---|
| decode loop | host-driven `while` loop | on device: tok → forward → sampler → tok |
| submission | `execute()`, await every token | `submit()` returns immediately |
| sampling | closed WIT enum; new methods patch the engine | tensor programs authored in the epilogue |
| overlap | speculation chain in the runtime | run-ahead: several passes in flight |
| data plane | request frame marshaled per fire | `put` is a release-store; host reads a pinned mirror |
| failure | error returned from `execute()` | channel poison, surfaced at `take` / `read` |
| guest compute | host only | host and device |

### Before and after: a watermarking sampler

Greenlist watermarking biases a pseudorandom half of the vocabulary before
sampling. It exists in both releases, which makes it a fair comparison.

In 0.4 the only way to reach the distribution was to pull it to the host. Every
token, the full vocabulary crossed the WebAssembly boundary so that the guest
could add a bias and take an argmax:

```rust
// 0.4: inferlets/demo-watermark/src/lib.rs
for _ in 0..input.max_tokens {
    let mut pass = ctx.forward();
    pass.input(&pending);
    let h = pass.probe(last_idx, Distribution { temperature: 1.0, k: 0 });
    let out = pass.execute().await?;               // host waits here
    let (ids, probs) = out.distribution(h)?;       // full vocab to the host

    let chosen = watermark.sample_biased(ids, probs);   // bias on the host
    if stop_tokens.contains(&chosen) { break; }
    generated.push(chosen);
    pending = vec![chosen];
}
```

In 0.5 the bias and the draw are tensor operations in the epilogue, so they run
inside the pass. Only the sampled token is published to the host:

```rust
// 0.5: tests/inferlets/greenlist-watermarking/src/lib.rs
fn watermarked_sample(logits: &Tensor, green: &Tensor, rng: &Tensor,
                      delta: f32, vocab: u32) -> Tensor {
    let bias = select(green, broadcast(delta, [vocab]), broadcast(0.0f32, [vocab]));
    gumbel_max(logits + bias, rng)
}

decode.epilogue(move || {
    let length = kv_len.take();
    let green_value = green.take();
    let rng_value = rng.take();
    let token = watermarked_sample(&intrinsics::logits(), &green_value,
                                   &rng_value, delta, vocab);

    let next_length = &length + 1u32;
    token_in.put(&token);                  // feed the next pass
    kv_len.put(&next_length);              // advance the geometry
    positions.put(&length);
    page_indptr.put(indptr(1, &next_length.div_ceil(page_size)));
    token_out.put(&token);                 // surface to the host
    rng.put(&rng_value + iota(2));
});
```

Note what did **not** change. The greenlist is keyed on the previous output
token, so the host cannot supply the mask for pass k+1 until pass k has settled.
This algorithm is inherently depth-1 and still round-trips once per token:

```rust
while submitted < budget {
    green.put(green_mask(vocab, previous, input.gamma));
    decode.submit(&pipeline)?;
    let token = token_out.take_host::<i32>().await? as u32;
    previous = token;
    // ...
}
```

The model does not remove round trips that the algorithm requires. What it
removes is the vocabulary-sized transfer, the host-side arithmetic, and the
round trips that were only an artifact of how generation was driven. Inferlets
whose next input does not depend on the host, which is the common case, keep the
pipeline full through `run_ahead` and never park per token.

A complete greedy sampler, from the `compiler/dsl` documentation: seeded RNG,
argmax over noised logits, and a token that feeds itself.

```rust
let tok = Channel::new([1], dtype::i32);   // input token ring
let indptr = Channel::from([0u32, 1]);
let out = Channel::new([1], dtype::i32);   // host reads sampled tokens
let rng = Channel::from([7u32, 0]);        // seeded RNG state
tok.put([1i32]);                           // seed BOS

let mut b = Builder::new(vocab, page_size);
b.bind_port(Port::EmbedTokens, &tok);
b.bind_port(Port::EmbedIndptr, &indptr);
b.stage(Stage::Epilogue, || {
    let logits = intrinsics::logits();
    let r = rng.take();
    let g = gumbel(&r, [intrinsics::vocab()]);
    let t = reduce_argmax(logits + g);
    rng.put(&r + Tensor::constant([0u32, 1]));
    tok.put(&t);                           // feed the next step
    out.put(t);                            // surface to the host
});

let traced = b.build()?;                   // canonical container bytes
```

The token loop closes on the device: `tok`, forward, sampler, `tok`. Adding a
sampling method is a new trace, not a new enum variant.

- Channel effects are transactional per fire. A pass either commits all of its
  puts or publishes none of them.
- The host side is async: `put`, `take`, `read`. The host never sequences steps;
  it parks on `take` when it needs a value.
- A fault poisons the channel. `take` and `read` surface the failing fire's
  cause rather than hanging.

Channels are the only stateful construct in the model, and the same handle binds
into the pass and serves the host API.

The scores are captured inside the attention kernel, not recomputed afterwards.
Not every model exposes them.

In 0.4 this had no expression at all. There was no stage between the layers to
attach code to, and the attention weights never left the kernel.

`on_attn` fires once per layer, and an inferlet cannot ask the model how many
layers there are, so the layer loop folds into a device-carried channel that the
epilogue publishes once per fire:

```rust
// 0.5: tests/inferlets/tova-attention/src/lib.rs
let acc = Channel::from(vec![0.0f32; kv_max as usize]).named("tova_acc");
let layer_ct = Channel::from([0u32]).named("tova_layers");

fwd.on_attn(move || {
    let prev = acc.take();
    let ct = layer_ct.take();
    let scores = intrinsics::attn_score(kv_max);   // this layer's softmax weights
    acc.put(&(&prev + &scores));
    layer_ct.put(&(&ct + 1u32));
});
```

### Prefill chunking

Not a scores feature, but the other pass-level limit that moved to the guest.
Chunking is now selected by the inferlet, which removes the previous one-shot
prefill ceiling of 8192 tokens on the tested configuration. Each chunk attends
over the full prefix written so far, so chunking does not change results.

## Recurrent state

0.4.0 had no recurrent-state interface; `recurrent` and `fold` do not occur in
its WIT surface. 0.5 adds one.

A KV cache is append-only, so forking a context is O(1). Recurrent state is
updated in place, which does not admit the same treatment. The 0.5 model is a
folded prefix plus a mutable buffer.

| Operation | Meaning |
|---|---|
| `fold` | Advances the folded boundary. Irreversible. Semantically a no-op; reclaims memory and compute. |
| `buffer` | Writable suffix where new recurrent tokens land. |
| `commit` | Advances the accepted prefix during speculative decode. |
| `discard` | Drops a rejected buffered tail without folding it. |
| `fork` | Copy-on-write branch. |

- Speculative decoding works against recurrent models. The accepted count is
  device-resident, so verify and commit fuse into one fire rather than
  round-tripping through the host.
- Rollback covers the unaccepted buffered tail. A committed `fold` cannot be
  undone; the pre-fold state survives only via a prior `fork`.
- RS mappings are published at prepare time, which keeps them valid under
  run-ahead scheduling.
- A single fire can fold one request while only buffering another.

Currently exercised by hybrid models: Qwen3.5 GDN linear attention and
Nemotron-H Mamba2. The pure `recurrent` pass kind exists but no registered model
uses it.

Guest code runs inside the pass at its stage; it adds no kernel launches and no
host round trips.

Implementation notes:

- `compiler/` contains no hand-written C++, and code generation takes no
  device-architecture input, so it is tested without a GPU.
- `compiler/eval` is a reference interpreter that pins semantics: integers
  bit-for-bit, floats to ULP. Every backend is diffed against it.
- One artifact crosses every language: the Rust host, the C++ CUDA driver, and
  the wasm SDKs.

The inferlet WIT surface is split by state class into `forward` (KV only),
`forward-recurrent`, and `forward-hybrid`, selected by `model.pass-kind()`.
Binding an attention-only algorithm to a recurrent model is rejected at the
interface rather than at runtime. Models also publish their own constraints,
such as frame size and channel capacity.

## Breaking changes

- Existing inferlets must be rewritten. The eager `execute()` loop is
  replaced by traced dataflows and channels.
- Samplers are no longer a WIT enum. A sampler is an epilogue closure over
  logits. The constraint layer is removed in favor of the grammar interface.
- The inferlet WIT surface is split into `forward`, `forward-recurrent`, and
  `forward-hybrid`. Inferlets select via `model.pass-kind()`.
- The vLLM, SGLang, TensorRT-LLM, and portable drivers are removed.
  `driver/` now contains `cuda`, `metal`, `dummy`, and `transport`. Their
  reference documentation is removed with them.
- The repository layout changed. The single `runtime/` crate, `server/`, and
  `inferlets/` are replaced by a 55-crate workspace. `interface/` is the
  dependency floor and holds the boundary contracts; `controller`, `gateway`,
  and `worker` do not depend on one another.
- The SDK spelling changed. Tensor math uses operators rather than function
  calls; a `take` is a tensor and a host readback is not a `take`; channels
  carry their own identity; dtypes have a single lowercase spelling.
- MCP and messaging documentation is removed.
- `CHANGELOG.md` and `Dockerfile.cuda` are removed.

## Smaller changes

**Distributed control plane.** `controller` handles pairing, roles, and health.
`driver/transport` is a worker-to-worker P2P KV-tensor data plane over
NIXL/RDMA. The gateway exposes `POST /v1/generate` (SSE) and `GET /v1/ws`.

**Grammar matcher** gains fork, rollback, and rollback capacity. Compiled
grammars survive forks, which constrained speculative decoding and ASAP
grammar-aligned decoding both require.

**CLI.** `pie config`, `pie model`, `pie driver`, and `pie serve`. `pie-env`
prints the resolved configuration without starting a daemon.

**Sandboxing.** Filesystem and network policy is set per inferlet instance.

**Observability.** Tracing and OTLP metrics, including scheduler and fire
timing.

**Test infrastructure.** Tokenizer output is checked against official Hugging
Face and tiktoken snapshots, CI runs MLX parity validation, and PTIR has golden
traces and drift checks.

**Model layer.** Chat templates, reasoning parsers, tool-call templates, and
multimodal geometry now live in one place.

## Known gaps

- Writing an inferlet that computes on tensors is harder than writing one that
  did not. Shape and dtype errors surface at bind time rather than at the call
  site that caused them.
- Quest and TOVA compute their keep-sets but do not yet act on them.
- The agent-orchestration, MCP, messaging, and multimodal examples from 0.4 have
  no 0.5 counterpart, and there are no Python or JavaScript example inferlets.
- No documentation for recurrent state.
- No Metal driver reference page; only CUDA has one.
- Benchmark numbers are preliminary, measured by us, and not yet reproducible
  from a published harness.
- The Metal host fit check is conservative enough to refuse models that run. On
  a 32 GiB M1 Max it refuses four of five measured models.
